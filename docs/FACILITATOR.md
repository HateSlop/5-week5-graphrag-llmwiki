# 세션 진행 가이드

함께 볼 본문은 노션과 `notebooks/`에 있습니다. 이 문서는 실행 전 준비와 화면이 막혔을 때의 복구 방법을 정리합니다. D1–D6의 인물·팀·일정은 전부 가상입니다. 별도 설치나 과제는 필요하지 않습니다.

## 수업 전 준비

1. Conda Python 3.12 환경을 만들고 `requirements.txt`를 설치합니다. Microsoft GraphRAG도 실행할 예정이면 `requirements-microsoft.txt`까지 설치합니다.
2. `python scripts/build_notebooks.py`를 실행한 뒤 네 노트북이 열리는지 확인합니다. `python scripts/verify_demo.py`로 **오프라인 경로**를 점검합니다.
3. Neo4j 화면을 사용할 경우 접속을 켜고 `.env`의 `NEO4J_*` 값을 채웁니다. `02` 노트북의 Browser 쿼리를 미리 실행해 그래프가 보이는지 확인합니다.
4. Microsoft GraphRAG를 실제로 보여줄 경우 `python scripts/prepare_microsoft.py --format text`, `python scripts/microsoft_cli.py index --root runs/microsoft --method standard --dry-run --skip-validation`, 같은 래퍼로 실제 `index` 순서로 실행합니다. dry-run은 모델 연결을 점검하지 않습니다. API 호출 비용이 있으므로 인덱싱 완료 산출물을 **수업 전에** 마련합니다. 표·그림·출처를 D1–D6와 대조합니다.
5. `04` 노트북의 기본 fixture 흐름을 한 번 실행해 D6 전후 diff와 query/lint 화면을 확인합니다. Obsidian에서 출력된 `runs/.../vault`를 엽니다. API 키가 있으면 실제 LLM 계획도 별도 vault에서 예행연습합니다.
6. 화면 배율과 한글 글꼴을 확인합니다. Chroma 검색 순위는 **실행 결과를 캡처**해 둡니다. 임베딩/문장 구성에 따라 특정 ID가 몇 위인지 보장하지 않습니다.

## 권장 진행 순서

| 순서 | 화면 | 전환 질문 |
| --- | --- | --- |
| 1 | 노션 01, 노트북 01의 A·B·C | “B가 검색에서 빠지면 무엇을 말할 수 없나?” |
| 2 | 노트북 01 D1–D3 Chroma 순위 | “실제 top-2에서 어떤 근거가 없나? k=3이면?” |

| 4 | 노트북 03 준비된 Parquet·Local/Global | “자동 추출의 어느 관계를 원문으로 되돌아가 확인해야 하나?” |
| 5 | 노션 03, 노트북 04 초기 위키 | “raw와 wiki가 다르면 어느 쪽을 기준으로 확인하나?” |
| 6 | D6 ingest diff·query·lint | “새 요약 하나 외에 기존 어느 페이지가 바뀌었나?” |
| 7 | Obsidian 링크 그래프·비교·질문 | “위키 링크의 선과 Neo4j 관계의 선은 각각 무엇을 뜻하나?” |

시간이 부족하면 Neo4j 화면보다 `02`의 로컬 그림으로 관계를 먼저 보여주고, Microsoft GraphRAG의 실제 인덱싱 실행은 생략한 채 **미리 생성해 원문과 대조한 산출물**만 봅니다. 자료가 더 길어야 Global Search가 강점을 보이는 질문이 생길 수 있습니다. 여섯 문서의 Global 답변을 성능 검증 결과로 말하지 않습니다.

## 장면별 설명과 판정 기준

### 정책 A·B·C

- 전체 근거의 정답: 2025년 4월 가입자는 적용 대상이지만, 해외 송금 수수료는 예외이므로 **면제되지 않는다**.
- A·C만 제공하는 통제 장면에서는 “면제된다”고 단정하면 위험합니다. **예외 여부를 판단할 근거 B가 없다**가 적절합니다.
- 부모 정책/이웃 청크 회수로 같은 RAG도 개선될 수 있음을 즉시 보여줍니다. 이 사례를 그래프의 독점적 해결 능력으로 설명하지 않습니다.

### D1–D3와 top-k

- Chroma의 **실제** 검색 순위와 ID를 읽습니다. top-k=2이면 셋 중 최소 하나가 빠집니다. 빠진 ID에 따라 말할 수 없는 연결이 달라집니다.
- D1: 오헤슬의 프로젝트 총괄, D2: 프로젝트의 프로그램 소속, D3: 보안팀의 프로그램 검토.
- 세 문서가 모두 있어도 확인되는 답은 **“같은 프로그램을 통해 연결된다”**입니다. 직접 협업 사실은 주어진 자료에 없습니다.
- k=3 또는 개선된 벡터 검색도 기준선으로 인정합니다. 그래프는 관계 질문을 반복할 때 경로를 명시적으로 저장·회수하는 선택지입니다.

### Neo4j와 Microsoft GraphRAG

- `02`의 그래프는 교육을 위해 `graph_facts.json`에 사람이 검증한 관계를 넣은 것입니다. 자동 추출 성공 사례라고 말하지 않습니다.
- Neo4j Browser의 `source_id`/`evidence`를 눌러 각 선의 D1–D3 원문을 보여줍니다. D2가 없으면 경로가 끊기는 셀도 실행합니다.
- `03`에서는 Microsoft의 **실제** `relationships.parquet`와 `text_units.parquet`를 비교합니다. Microsoft GraphRAG 기본 저장은 Neo4j가 아닙니다.
- Local Search는 엔터티 중심 문맥, Global Search는 커뮤니티 보고서 중심 문맥을 사용합니다. 이번 실제 출력에서 Local은 직접 협업을 단정했고, Global은 D5 문서 ID를 프로젝트로 오인하며 일정 변경 이유를 추측했습니다. `03`의 원문 경로 감사와 저장된 답변 보기 셀에서 두 오류를 나란히 확인합니다. 자동 추출과 보고서가 틀리면 생성 답변의 `[Data: ...]` 표시만으로 사실을 보증할 수 없습니다.

### LLM Wiki

- `raw/`는 변경하지 않는 원문, `wiki/`는 기존 페이지를 갱신하는 지식, `AGENTS.md`는 작업 규칙입니다. `index.md`는 주제별 지도, `log.md`는 시간순 기록입니다.
- D6 전에는 현재 목표일이 2025-11-03, D6 후에는 2025-11-10입니다. 11월 3일은 **이전** 목표일로 남아야 합니다. 수정 완료 여부는 D6만으로 알 수 없습니다.
- 기본 fixture는 **미리 쓴 변경 계획**입니다. 실제 에이전트 ingest 장면은 `--mode llm`으로 따로 실행합니다. 모델 출력이 늦거나 잘못되면 fixture diff로 원리를 보여주되, 생성 주체를 분명히 밝힙니다.
- `lint`의 깨진 링크·출처·현재 날짜 점검은 코드 기반이며, `--llm`은 의미상 모순과 조사 공백을 추가로 찾아보는 유료 호출입니다. 둘의 결과를 구분합니다.
- Obsidian 그래프의 선은 페이지 링크입니다. Neo4j의 타입 있는 사실 관계와 같은 의미로 읽지 않습니다.

## 화면이 막힐 때

| 증상 | 바로 사용할 화면 | 이후 조치 |
| --- | --- | --- |
| Neo4j 접속 실패 | `02`의 NetworkX 그림과 경로 표 | `.env`의 URI·암호, 서버 상태 점검 |
| Microsoft 인덱싱 지연/실패 | `03`의 입력·공식 흐름 설명과 수업 전 캡처한 **실제 결과** | API 키·모델·`runs/microsoft/logs`와 `output` 확인 |
| PDF에서 한글/표 누락 | UTF-8 텍스트 입력 여섯 개 | OCR·추출 결과와 원문 비교 후 재색인 |
| 위키 LLM 계획이 잘못됨 | `fixture` 계획의 diff | `runs/.../D6_live_plan.candidate_*.json`과 원문을 대조하고, 검증을 통과하지 않은 계획은 적용하지 않음 |
| 노트북 재실행 | `04`는 새 `runs/wiki_notebook_...` vault 생성 | 이전 runs는 보존; 필요한 것만 나중에 정리 |
